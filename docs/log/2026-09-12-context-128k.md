# 2026-09-12 Increase the FP8 context window to 128K

Status: in progress
Profile: a-int4draft, FP8 KV, MTP4

## Hypothesis

The validated FP8 configuration's 191,566-token cache can serve a 131,072-token context window correctly, including requests longer than the previous 98,304-token limit.

## Configuration

Change only maximum context from 98,304 to 131,072. Keep the pinned engine and model, FP8 KV, INT4 draft, MTP4, vision, GPU utilization 0.95, one sequence and 8,192 batched tokens.

```bash
ssh vllm 'cd ~/Code/llm-server && git pull --ff-only'
ssh vllm 'cd ~/Code/llm-server && KV_DTYPE=fp8 MAX_MODEL_LEN_INT4DRAFT=131072 bash scripts/compose.sh --profile a-int4draft up -d --no-deps vllm-a-int4draft'

# Validate actual long requests from mbp after startup:
python3 eval/context_check.py --prompt-tokens 126000 --out eval/results/2026-09-12-fp8-context/fp8-128k-context.json

# Restore the pre-experiment serving configuration:
ssh vllm 'cd ~/Code/llm-server && KV_DTYPE=auto MAX_MODEL_LEN_INT4DRAFT=98304 bash scripts/compose.sh --profile a-int4draft up -d --no-deps vllm-a-int4draft'
```

Baseline: [FP8 at 96K](2026-09-12-fp8-int4draft.md), which passes 18/18 short checks, 3/3 archive retrieval/continuation checks at about 90K input tokens and 8/8 Pi xhigh coding/image tasks. The separate `MAX_MODEL_LEN_INT4DRAFT` override preserves the FP16 rollback profile's 98,304-token default.
