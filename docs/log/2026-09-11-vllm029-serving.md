Status: in progress, candidate initializing
Profile: a-int4draft, MTP4, no CPU pinning

## Hypothesis

The released XPU engine and newer XPU kernels reduce serving overhead while preserving the current model, draft overlay, tool calling and vision behavior.

### Candidate startup

The candidate container started at 13:51:32 UTC. The API startup confirms version 0.29.0 and the same serving flags, including MTP4. Model loading took 12.59 s and reported 17.73 GiB. Logs show the five MTP linear layers being requantized to INT4. The draft LM-head conversion has not yet appeared because it initializes when logits are first computed.

The loading messages originate from `vllm/v1/worker/gpu/model_runner.py`, the V2 runner. The installed `xpu_worker.py` dispatches to `XPUModelRunnerV2` when `use_v2_model_runner` is true; its V1 path uses `gpu_model_runner.py`, which produced the old image's logs. The API's "V1 LLM engine" label refers to the engine architecture and does not mean the V1 model runner was selected.

Transformers printed these processor-documentation errors and continued loading:

At this point there is no serving result or speed measurement. These messages alone are not evidence of a GPU or vision failure. Raw startup output is saved in `eval/results/2026-09-11-tuning/v029-startup.log`.

The candidate is healthy and passed 18/18 repeated short-output cases. The draft LM-head INT4 conversion also executed, confirming both overlay components are active. Startup reports 107,632 KV tokens versus the old MTP4 image's 109,067. Graph capture took 0.45 GiB versus 0.15 GiB; the 98,304-token context still fits. The controlled throughput, cold-request and corrected Pi task comparisons now begin.

The first screening row, six warm code repetitions with thinking off and concurrency 1, reports 8,251 actual input tokens, 768 generated, median decode 91.7 tok/s (sd 3.03), TTFT 0.882 s and 73.7% acceptance. The old MTP4 row was 94.1 tok/s (sd 3.95) at 8,248 input tokens. This does not establish a speed gain; the remaining workloads are running.
