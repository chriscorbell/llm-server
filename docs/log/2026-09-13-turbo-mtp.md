# 2026-09-13 Turbo Q6_K MTP2 on SYCL

Status: in progress
Profile: turbo-gguf

## Hypothesis

Two-token MTP will improve Turbo Q6_K's steady decode on SYCL without breaking text, tool calls or vision.

## Configuration

Change only `TURBO_SPEC_TYPE` from `none` to `draft-mtp`. The draft limit is already fixed at two, and the pinned GGUF contains its head. Keep the SYCL image, 65,536-token context, F16 KV, flash attention and all batch/sampling settings fixed.

```bash
ssh vllm 'cd ~/Code/llm-server && bash scripts/gpu-health.sh > scratch/turbo/before-mtp-health.log 2>&1'
ssh vllm 'cd ~/Code/llm-server && TURBO_SPEC_TYPE=draft-mtp bash scripts/compose.sh --profile turbo-gguf up -d --no-deps llama-turbo'
python3 eval/mtp_check.py --model qwen38-turbo --out scratch/turbo/sycl-mtp-short-checks.json
python3 scripts/bench.py --base-url http://vllm:8000 --model qwen38-turbo \
  --prompt-tokens 4096 --gen 256 --workload code --corpus-file scratch/turbo/bench-corpus.py \
  --warm --prompt-id turbo-profile-comparison -n 2 --json scratch/turbo/sycl-mtp-warm.json
```

Baseline: [SYCL without speculative decoding](2026-09-13-turbo-sycl.md), 19.7 tok/s and 0.214 s TTFT on 4,199-token warm code prompts, 256 generated tokens, concurrency 1 and thinking off. The benchmark now reads llama.cpp's unlabelled `llamacpp:spec_decode_*` counters using the same acceptance calculation as vLLM. The request corpus was frozen before that code edit.

## Measurements

The two warm repetitions use identical request hashes to the no-speculation baseline, with 4,199 actual input tokens, 4,195 cached tokens, 256 generated tokens, thinking off and concurrency 1:

| Metric | No speculation | MTP2 |
|---|---:|---:|
| Median decode | 19.7 tok/s | 34.8 tok/s |
| Median TTFT | 0.214 s | 0.224 s |
| Short checks | 18/18 | 18/18 |
| Draft acceptance | Not applicable | 85.6% |

MTP repetitions measure 35.0 and 34.7 tok/s. Position acceptance is 92.02% for the first draft token and 78.72% for the second. Near-limit context and coding/image checks are in progress. Raw benchmark data: `scratch/turbo/sycl-mtp-warm.json` on mbp.

## What happened

The backend comparison passed 18/18 short checks on SYCL. The next startup enables the existing draft head, with no separate draft-model file.

MTP startup reaches the listening socket in 71.946 s. The log confirms `creating MTP draft context against the target model`, with no separate weight copy. All 18 short checks pass again, including three successive tool-call requests. The rendered-template token count is also checked against a completed request: 27 tokens for the addition case, matching `usage.prompt_tokens`. This validates the llama.cpp adapter in `eval/context_check.py` before the long run.
