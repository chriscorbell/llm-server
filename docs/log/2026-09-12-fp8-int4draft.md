# 2026-09-12 FP8 KV with the INT4 draft

Status: in progress
Profile: a-int4draft, original pinned image, MTP4

## Hypothesis

FP8 KV can increase cache capacity while preserving the current INT4 draft's coding, reasoning, tool and vision behavior at a 98,304-token window.

## Configuration

Change only the cache dtype from `auto` (FP16 with the current model dtype) to `fp8`. Keep context 98,304, GPU utilization 0.95, batched tokens 8,192, one sequence, vision, INT4 draft and MTP4. The engine remains pinned to `sha256:f01e24f6c7ff01f1e0662234255a1372297d1dbd89d003cf13c8fad3eab1ba4f`.

```bash
# On mbp, commit and push the parameterized compose file first.
ssh vllm 'cd ~/Code/llm-server && git pull --ff-only'
ssh vllm 'cd ~/Code/llm-server && KV_DTYPE=fp8 bash scripts/compose.sh --profile a-int4draft up -d --no-deps vllm-a-int4draft'
# Rollback:
ssh vllm 'cd ~/Code/llm-server && KV_DTYPE=auto MAX_MODEL_LEN_BF16KV=98304 bash scripts/compose.sh --profile a-int4draft up -d --no-deps vllm-a-int4draft'
```

Baseline: [September 11 identical-request checks](2026-09-11-mtp-fixed-prompt-confirmation.md). This run will also collect fresh measurements before changing the cache.

### FP8 cached code comparison

Both measured request hashes match the FP16 arm exactly: 31,015 input tokens, 512 generated tokens, thinking off, concurrency 1, two repetitions. FP8 decode is 80.4 tok/s (79.1 to 81.6) versus FP16's 79.1 (78.4 to 79.8). This small sample does not establish a decode speed change. MTP acceptance is 75.2% versus 71.8%. Cached TTFT rises from 0.893 to 2.358 s, while reused prompt tokens fall from 29,952 to 28,288. The larger FP8 cache blocks leave more of this specific prompt to prefill; cached latency depends on block alignment as well as dtype.

### FP8 cold code and 90K retrieval

Cold code at a median 31,037.5 actual input tokens, 256 generated tokens, thinking off, concurrency 1 and two repetitions measures 20.151 s TTFT, 1,540.3 tok/s effective prefill and 75.1 tok/s decode. FP16 measured 17.579 s, 1,765.6 tok/s and 78.0 tok/s. FP8 increases TTFT by 14.6%. Both arms use the same corpus and sampling seeds; cold nonces differ. MTP acceptance is 69.1% versus 70.2%.

The FP8 archive check passes 3/3. All three complete request hashes match FP16, including the continuation. At 89,987 input tokens and 126 generated tokens, concurrency 1 and thinking off, FP8 cold TTFT is 87.090 s versus 72.825 s, a 19.6% increase. FP8 decode is 84.65 tok/s versus 75.74 on this synthetic checksum output. Repeated retrieval starts in 3.040 s and continuation in 3.108 s, with 88,192 cached tokens on each, versus FP16's 89,024. The continuation has 90,146 input tokens.
