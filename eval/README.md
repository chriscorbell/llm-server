# Task suite

Eight pass/fail coding tasks used to score a Profile's behaviour rather than its speed. Each task gets a fresh copy of its fixture in a temporary directory, so tasks cannot contaminate each other and a run is repeatable.

The outcome comes from the task's `verify.sh`, not from reading the model's prose. A model that explains a correct fix without applying it fails, which is the point.

## Running it

```bash
./eval/run.py --model llm-server/qwen38
```

Run the same tasks through Pi:

```bash
./eval/run.py --client pi --model llm-server/qwen38 --thinking xhigh
```

Check reasoning replay, request sampling and remembered requirements after compaction:

```bash
python3 eval/pi_contract.py --out eval/results/pi-contract
```

This uses a temporary project, the checked Pi configuration and three generated files of archival records. It checks that an early CSV-header requirement survives automatic compaction, falling back to manual compaction if the threshold was not reached. `requests.jsonl` records numeric request settings, reasoning-presence counts, actual usage and time to the first streamed delta. It excludes request headers and raw payloads. The full RPC transcript is kept separately in the ignored results directory.

Results land in `eval/results/<timestamp>/`: a `summary.md`, a `summary.json`, and the full agent transcript per task. That directory is gitignored; copy the numbers into a log entry instead.

Node 24 and Python 3 are the only requirements, plus Chrome for the vision task. No package installs, so the suite runs offline.

## The tasks

| Task | Exercises |
|---|---|
| 01 ts add feature | Writing a new function against an existing test contract |
| 02 ts fix bug | Reading a loop bound correctly, an off-by-one that three tests pin down |
| 03 ts refactor | Removing duplication without changing behaviour, checked both ways |
| 04 py add feature | Extending a function signature and wiring it through a CLI |
| 05 py fix bug | Integer division where ceiling division was meant |
| 06 multifile trace | Following a wrong value across four files to a single inverted assignment |
| 07 long context | Finding one non-conforming handler among 240 in a large generated file |
| 08 vision css | Reading a screenshot to identify a layout defect that the CSS alone does not reveal |

Task 07 is the context-window test. Its fixture is generated by `setup.sh` so the repository stays small, and the generator is seeded, so the bug lands in the same handler every time.

Task 08 attaches `screenshot.png`. The defect is that the main content sits underneath a fixed sidebar, which is visible in the image but not obvious from the stylesheet.

It is skipped by the opencode harness. opencode 1.18.27 attaches images with mime type `text/plain`, so the model receives a text file rather than an image and the task ends up measuring the client. Pi sends the screenshot as image input and runs the normal verifier. Score vision directly through the API with:

```bash
./eval/vision_check.py
```

That sends the same screenshot as a proper image part and checks the returned stylesheet with the same headless layout verifier, so a pass means the same thing. Set `EVAL_CLIENT_SENDS_IMAGES=1` to re-enable the opencode path once the client is fixed.

## How the suite was validated

Every task was run twice before the model ever saw it, once on the untouched fixture and once with a known-correct fix applied by script, to prove it discriminates in both directions. That pass found two defects in the suite itself. See [the build entry](../docs/log/2026-09-07-eval-suite-built.md).

## Adding a task

Create `tasks/NN-name/` with `prompt.md`, `fixture/`, and an executable `verify.sh` that exits 0 on pass and 2 to skip. Add `setup.sh` if the fixture must be generated. `verify.sh` runs with `TASK_DIR` pointing at the task directory, so it can reach files kept outside the fixture, which is how the vision check stays tamper-proof.

Write the verifier so that deleting the problem does not pass it. Task 03 checks that the duplicated rule appears exactly once; task 07 checks that all 240 handlers survive.
